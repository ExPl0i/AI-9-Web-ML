## Модель машинного обучения как веб-сервис

Пятое занятие Темы 4 «Разработка веб-приложений» курса «Искусственный интеллект» для 9 класса. Модель определения покрытия из итоговой работы Темы 1 становится частью сервиса «Покрытие»: она отвечает на запросы по сети, проверяет входные данные и записывает каждый прогноз в журнал в базе данных PostgreSQL из Т4.Б1.4. Ученики загружают конвейер scikit-learn один раз при старте сервера, проверяют 14 признаков сначала вручную, затем моделью Pydantic, отвечают классом и вероятностями всех классов и хранят прогнозы в столбцах `jsonb`. Водитель сообщает, какое покрытие было на самом деле, а сервис считает долю верных прогнозов одним запросом SQL. Задания проверяются тестами `pytest`. Занятие продолжает практическую работу №2 по программе.

## Теория (презентация и ноутбук)

1. **Модель в файле.** Путь модели из ноутбука в сервис: клиентам нужен контракт, а не scikit-learn. Сохранение всего конвейера функцией `joblib.dump` вместе с паспортом модели: версия, признаки, классы, версии библиотек, метрики. Почему нельзя загружать чужие файлы `pickle` и `joblib`: при загрузке выполняется код из файла. Совпадение версий библиотек при обучении и в сервисе, файл `requirements.txt`. Загрузка модели один раз при старте: функция жизненного цикла `lifespan`, хранилище `app.state`, замер времени загрузки и прогноза.
2. **Проверка входных данных.** Модель отвечает на любые числа: код ошибки датчика `-999` превращает сухой асфальт в лед. Три вида ошибок: нет признака, неверный тип, значение вне диапазона; ответ 422 с именем признака. Ручная проверка и ее ловушки (`True` – подкласс `int`, значение NaN). Модель Pydantic с границами `ge` и `le`, строгим режимом, описаниями и запретом лишних полей; описание признаков в `/docs`.
3. **Прогноз и журнал.** Путь запроса через сервис. Ответ: класс, вероятности всех классов, версия модели, время. Порядок вероятностей задает `pipeline.classes_`. Журнал прогнозов в PostgreSQL: тип `jsonb`, операторы `->` и `->>`, обертка `Jsonb` в psycopg. Обратная связь водителя и доля верных прогнозов одним запросом с `COUNT(*) FILTER` и `NULLIF`.
4. **Практика.** План из шести заданий, первый запуск, проверка командой `pytest`.

## Практическая работа

| Задание | Что пишем | Главный результат |
| --- | --- | --- |
| З1 | `load_model` в `app/ml.py` и функция `lifespan` | модель загружается один раз при старте; другой файл, нет ключей, другая версия scikit-learn – понятная ошибка |
| З2 | `validate_features` в `app/features.py` | ручная проверка 14 признаков: все ошибки сразу, по порядку признаков |
| З3 | модель Pydantic `Features` | те же ошибки дают 422 с именем признака, лишний `rec_speed` отклоняется, описания признаков в `/openapi.json` |
| З4 | `predict_one` и `POST /api/predict` | класс и вероятности совпадают с эталоном для десяти примеров, в ответе версия модели и время |
| З5 | таблица `predictions` в `schema.sql` и запись в журнал | каждый прогноз в базе: признаки и вероятности в `jsonb`, версия модели; неверный запрос не записывается |
| З6 | `POST /api/predictions/{prediction_id}/feedback` и `GET /api/predictions/accuracy` | обратная связь водителя, доля верных прогнозов одним запросом SQL |

Задания повышенной сложности: пакетный прогноз по файлу CSV (`UploadFile`), поиск прогнозов по значению признака внутри столбца `jsonb`, сравнение двух версий модели на одних запросах.

Домашнее задание: довести задания З1–З6; шаг прототипа – подключить к своему проекту модель или вычислительное ядро за отдельной функцией и модель Pydantic для входных данных.

## Как работать

Нужен сервер PostgreSQL с ролью и базами из Т4.Б1.4 (вариант запуска выбирает преподаватель) и файл `.env` (можно скопировать из Т4.Б1.4).

```
cd ПР_ML_сервис/server
python -m pip install -r requirements.txt   # версия scikit-learn должна совпасть с версией модели
copy .env.example .env                       # вписать свой пароль или взять .env из Т4.Б1.4
python -m app.init_db                        # таблицы в рабочей базе (после З5 – еще раз)
pytest                                       # проверить все задания
pytest tests/test_z4.py -v                   # проверить одно задание
pytest -m extra                              # задания повышенной сложности
fastapi dev app/main.py                      # запустить сервер: http://127.0.0.1:8000/docs
```

## Требования

Python 3.12 или новее, библиотеки из `requirements.txt` (FastAPI 0.162.0 со стандартным набором, psycopg 3.3.8, pydantic-settings, scikit-learn 1.9.1, joblib, numpy, pandas, pytest) через школьное зеркало PyPI, сервер PostgreSQL 18 (архив для Windows без установки или Docker Desktop с образом `postgres:18`), браузер Chrome или Edge, редактор VS Code. Порты 8000 и 5432 должны быть свободны. Если в школьной сети закрыт доступ к cdn.jsdelivr.net, для страницы `/docs` нужны три файла в папке `server/static/docs` (список – в README этой папки).
